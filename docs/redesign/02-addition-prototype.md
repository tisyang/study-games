# 任务 02：加法“收苹果”互动样板

## 范围

只在 currentMode === 'add' 启用新探索流程。混合模式抽到加法仍可复用原加法展示与动画，不能意外改变混合轮次、计时或推进方式。减乘除、语文、英语保持既有行为。

## 页面与状态

- 顶部：返回、星星、声音；任务区标题“帮松鼠收苹果”，小进度“1 / 5”。
- 加法一轮固定 5 题，没有倒计时条和计时任务。不要把其他模式也改成 5 题。
- 任务仅一句话，例如“合起来有多少个苹果？”；大算式“28 + 15 = ?”。数字和操作区优先。
- 大果园场景：一个清楚的小松鼠、原先两堆十个一箱与散装苹果、醒目的 28 / 15。十个一箱必须明确标“10”，不能让孩子猜箱内数量。
- 点击“合在一起”后，同屏展示合并的箱子与散装苹果；有进位时显示十格装箱区，点击“装满一箱”把十个散装转成一个整箱（带短音效和明显变化），保留余下散装。无进位时合并即可，不出现无意义装箱按钮。
- 这两个操作是可选的思考工具；答案从一开始可选，熟练孩子可直接答题。合并/装箱不要显示最终总数答案；保留箱数和散装让孩子自己想。
- “合在一起”/“装满一箱”不能反复叠加；每题状态重新初始化。不把正确答案或计算过程塞成长段提示。
- 四个答案大按钮，使用原智能干扰项。桌面按空间排布，手机 2×2；不缩小数字来强求一行。

## 错误与帮助

- 选错：轻微视觉反馈＋一句“再试试”；选项仍可选，连击沿用既有规则。
- 原“错两次弹文字锦囊”在该模式改成场景内提示：“把苹果合在一起看看”或“十个苹果能装一箱”。高亮相应操作按钮。
- 始终有“帮帮我”按钮，提供同样提示。不得打开长文字 modal，不直接给出答案，也不新增计时。
- 连续点击、帮助、返回不留悬挂回调，不导致其他题被操作。

## 正确与推进

- 答对：保留已选正确按钮，锁住答案和操作，场景合并成正确箱数＋散装，短句“装好啦！”；松鼠收到苹果，短庆祝即可，不强制播放旧 4.8 秒演算。
- 在算式处显示完成后的正确等式。底部出现大“下一车 →”（最后一题“完成啦 →”）按钮，由孩子主动推进。每题只推进一次，返回后旧事件不能切题。
- 仍然每题正确奖励一颗星。结算保留现有星星奖励层级，但阈值按 totalQuestions 比例计算，不能硬编码 score === 10。五题全完成的奖励与十题全完成保持原奖励规则，不新增经济体系。
- 结算的“答对题数”改为“完成题数”（该项目允许重试直到正确，不能伪装首次正确率）。本轮最高连击仍展示。
- “再玩一次”仍五题，返回学科大厅正常；随后进入其他模式恢复十题与原计时。

## 实现约束

以 js/app.js、js/visual.js、index.html、css/style.css 的最小必要变更实现。探索分支明确传入渲染器，勿以 q.type === 'add' 独自判断全局模式。不要改题库与随机数范围，不新增框架、依赖、外网图片或音频。

为装箱操作采用真实按钮、focus-visible、可见名称；状态反馈可用轻量 aria-live。清理本次添加的事件、DOM 和状态。prefers-reduced-motion 下仍能立即得到正确最终状态。

## 必须验证

1. 28+15：合并后 3 箱＋13 散装；装箱后 4 箱＋3 散装；操作前后答案一致。
2. 21+14：合并后 3 箱＋5 散装，没有装箱按钮。
3. 19+19：合并后 2 箱＋18 散装；装箱后 3 箱＋8 散装。
4. 直接答对、不点工具也能正常下一题；操作后答错/求助/答对也能完成。
5. 五题只结算一次，重玩归零进度，返回再进入其他模式不遗留状态。
6. mix 模式中的加法仍有原演算和自动推进；其他七种模式保持十题和既有计时。
7. 手机无横向溢出，允许滚动；平板和电脑场景、算式、按钮清楚，不能为免滚动把字号压小。
