# 加法样板第一轮代码审查修正

本文件由 Codex 根据实际代码与验收结果增补，交由 agy 修正。仅处理下面列出的具体问题。

## R1：合并时不能重复展示待装箱的十个苹果

当前 merged 状态同时在 ones-items 展示全部散装苹果，又在 ten-pack-frame 额外展示十个苹果。28＋15 的画面因此会出现 13＋10 个散装，而非实际的 13 个，孩子数图会得到错误结果。

改为：有进位时，把现有散装直接分成十格框内的 10 个＋框外余下的 3 个，不能额外复制。无进位仍显示全部散装。装箱后框内十个消失、转为一个标 10 的新箱，框外余下不变。十格框必须确实为 2×5 或 5×2 十个位置。

## R2：进一步缩短场景内文字

主任务、角色气泡、舞台标题、装箱提示、按钮不能重复解释同一件事。建议：

- 主任务保留“合起来有多少个苹果？”。
- 初始气泡最多“帮我收苹果吧！”，不要再复述主任务或写长操作说明。
- 两堆只标数字（28 / 15），不重复“树上摘的”“小鹿运来”等标签。
- 合并气泡“十个装一箱”，十格框提示“10 个 → 1 箱”；无进位“数一数苹果吧”。
- 装箱后气泡“选个答案吧”，删除重复的 packed-status-badge 长说明。
- 完成气泡仅“装好啦！”，由大“下一车”按钮负责行动引导；删除另一个重复的“答对啦！苹果全部装好！”大标题。

## R3：维护约束

- 新增提示高亮的清除计时，使用现有 _registerTimer，保证 clear() 可清理。
- completeExploreAddition 如果不使用参数 q，去掉该参数及调用处实参。
- 不修整无关旧代码；本轮修正也不另加框架、抽象层或配置。

## R4：最后一步与退出后的推进防重

当前 btn-next-question 只检查 mode 和 isLocked；最后一题完成后 isLocked 仍为 true，旧按钮如果再触发会再次执行结算、重复发奖励。退出大厅后也不应接受旧推进事件。

推进事件同时检查答题视图可见、currentIndex < totalQuestions；接受推进后立即消费本次锁定状态（设置 isLocked=false），再进入 loadNextQuestion。这样连续事件只能推进一次，最后一题奖励只结算一次。不要为此增加复杂状态机或全局事件体系。

## R5：关键数字和任务文字仍偏小

当前新场景内 pile-num 只有 20px，工具按钮手机约 15px，主任务沿用约 17px；这没有达到本次重点突出、少字大字的目标。

- 在 #view-quiz 上按 currentMode === 'add' 切换单一 addition-explore 类，样式以此限定，不能影响 mix 中的加法。
- 加法主任务 24～28px、两堆数量 32px、操作工具至少 20px、角色短气泡至少 20px；手机也保留可读字号，宁可自然纵向滚动。
- 加法答案数字至少 32px，主算式沿用现有大字号即可。
- 删去场景叙述里重复的“收苹果”小标签；任务本身清楚即可。

## R6：场景主体不能继续缩在多层面板中

实际首版截图中，松鼠约 42px、苹果约 20px，内容仍被外层灰框、气泡框、展示板框、两堆框逐层包裹。要让角色与实物更突出：

- 仅在 addition-explore 内，将外层场景改为轻柔的草地/果园色背景；去掉 explore-display-board 的额外边框与内阴影，减少框套框。
- 松鼠放大到约 64px；场景里的苹果放大到 32px，箱子图标约 28px，箱上“10”至少 16px。
- 十格框明确两行五列，格子中的苹果能看清；窄屏不强行把两堆挤成很小的一行，可以换行。
- 保持算式与答案为清晰主操作，不给场景再添加新的文字、装饰面板或复杂动画。

## R7：最后收尾（R1～R6 已通过浏览器检查）

- 手机装箱后目前还留着“已合在一起”“已装满一箱”两个大灰按钮，挤占画面。合并后隐藏 merge，装箱后隐藏 pack，完成答题后隐藏整个工具栏；只保留当前还能使用的操作。DOM 按钮可保留，以 hidden 控制，无需重新设计状态。
- 删除本次新增、现已没有 HTML/JS 引用的 CSS 三个独立规则：`.merged-title`、`.pack-zone-remain`、`.packed-status-badge`。不要清理其他旧样式。
- 本轮不做其他功能或外观改动。
